# HR Valley — released APKs

The builds handed to devices, and the folder the in-app updater serves from.

| File | App | Installed by |
|---|---|---|
| `com.hrvelya.app.apk` | HR Valley | Every employee, on their own phone |
| `com.hrvelya.kiosk.apk` | HR Valley Kiosk | You, on the reception device |

## Publishing a release

1. Raise `versionCode` **and** `versionName` in `../WEB/android/app/build.gradle`
   (and the kiosk equivalent). `versionCode` is the integer phones compare — an
   unchanged one means nobody is ever offered the update.
2. Build: `cd ../WEB && npm run apk`
3. Copy the output from `../WEB/apk/` into `releases/` here.
4. Put the APK somewhere the phones can reach and point the API at it:

```jsonc
// API/src/HRVelya.Api/appsettings.json
"AppUpdate": {
  "LatestVersionCode": 2,
  "LatestVersionName": "1.1.0",
  "MinimumVersionCode": 0,          // raise only to force an update
  "DownloadUrl": "https://<host>/downloads/com.hrvelya.app.apk",
  "Notes": "One line the employee will read."
}
```

Read through `IOptionsMonitor`, so this takes effect without restarting the API.

## Forcing an update

`MinimumVersionCode` makes every build below it unusable until updated. Reserve it
for a security fix, or a server change the old build cannot speak to. A forced
update on a bad connection is an employee who cannot clock in.

## Why these are not built here

The Android projects are generated by Capacitor from the web app — `npx cap sync`
copies the built bundle into them. They therefore live with the source that
produces them, in `../WEB`, and only the finished artifacts land here.
